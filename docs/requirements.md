# 初步需求：Herdr TUI 全局订阅额度

## 已确认的用户需求

- 使用 Herdr TUI。
- 开发自己的订阅额度插件。
- 首期只支持 Codex，后续可扩展其他服务。
- 显示 5h 剩余额度和 1w 剩余额度。
- 全局显示。
- 在 Herdr 主界面持续可见，切换 workspace、tab、pane 后仍可见，无需打开专用 pane 或快捷键面板。
- 首期跟随本机 Codex CLI 当前登录账号，不提供独立登录或账号选择。
- 展示两个窗口各自的重置倒计时，优先采用进度条样式。
- 开发语言暂定 Rust。
- 项目目录：本仓库 `herdr-quota`。
- 首期只支持本机 Herdr server，读取同一机器上的 Codex 当前登录账号；不支持远程 server。
- 使用单行状态区显示；空间足够时跨 workspace、tab、pane 可见，接受窄屏时 Herdr 整体隐藏状态区。

## 首期验收目标

1. 读取当前所选 Codex 订阅账号的真实额度，分别展示 5h 和 1w 剩余百分比。
2. 空间足够的正常布局中，workspace、tab、pane 切换后额度仍可见；不要求当前 pane 正在运行 Codex。允许窄屏时 Herdr 隐藏状态区。
3. 明确标注“剩余”，避免将已用比例当作剩余比例。
4. 初次读取失败、未登录或账号不提供对应窗口时，显示未知或不可用，不伪造为 0% 或 100%。
5. 刷新失败时区分旧缓存与新数据，避免把过期值显示为实时额度。
6. 不把认证凭据写进项目文件或日志。
7. 展示 5h、1w 各自的重置倒计时，按分钟更新；缺失重置时间显示“重置未知”。倒计时归零时触发刷新，收到新数据前不自动补满额度。
8. 进度条填充部分表示剩余额度，额度减少时条缩短，同时保留百分比与“剩余”标记；首期使用终端字符条。
9. 每 60 秒读取额度；刷新失败后保留上次数据并标记“过期”，首次失败显示未知。检测到账号切换时立即丢弃旧账号缓存；跨进程账号切换的检测时机仍待验证。

上述显示、刷新和错误状态规则已在设计访谈中确认。首期采用两个短字符条的单行布局，接受窄屏隐藏；具体条宽通过显示验收调整。首期不包含历史趋势、多账号、多服务展示或远程 server 支持。

## 实现与验收状态

- 已实现 Rust `status`、`refresh` 与 `herdr-config` 命令；配置片段由程序生成，尚未写入用户的 Herdr 配置。
- [Herdr 展示能力](herdr-readiness.md)：隔离会话中的单行状态区已验证跨 workspace、tab、pane 可见；70 列隐藏，恢复 180 列后重现。显示验收使用固定示例数据。
- [Codex 协议](codex-readiness.md)：真实账号读取和 Rust 实现均已验证，返回 300/10080 分钟窗口；没有实际切换用户登录账号。
- 自动化测试覆盖窗口归一化、重置、过期、协议、账号变化与失败、缓存并发、路径转义和超时。真实跨进程账号切换、zoom、所有交互模式和重连仍待补充验收。

## 待验证的两个核心问题

### Herdr TUI 的全局展示入口

目标是常驻且跨 workspace 可见。先核对本机版本是否支持插件可写的全局状态栏、侧栏区域或显示 token。

官方 CLI 文档提供 pane/workspace 的 metadata token；这不能直接证明存在全局 token 或全局常驻区域。插件 pane 或 popup 也不能直接视为满足全局显示要求。若现有插件 API 无法满足，应先记录限制和备选方案，再决定是否需要修改 Herdr。

### Codex 订阅额度的数据来源

优先验证本机 Codex CLI/app-server 是否提供账号额度读取接口及更新通知，明确鉴权要求、字段含义、窗口时长和重置时间。

- 不用 token 消耗量估算订阅剩余额度。
- 不把 API 余额当作订阅额度。
- 不硬编码 primary/secondary 与 5h/1w 的对应关系，应根据接口返回的窗口信息验证。
- 已通过 Codex app-server 调用真实额度接口并验证 Rust 读取；程序不直接读取认证文件，不输出凭据或原始账号响应。

## 建议实施顺序

1. 验证 Codex 额度数据接口，保存脱敏后的字段示例。
2. 验证 Herdr TUI 全局展示入口，并确认切换工作区后的行为。
3. 使用 Rust 确定依赖，编写最小的“读取 → 归一化 → 展示”实现。
4. 加入刷新、缓存、错误状态和进程退出处理。
5. 本地 link 插件，验证真实额度和全局可见性。
